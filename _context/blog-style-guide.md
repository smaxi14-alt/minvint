# 블로그 문장·타이포 작성 기준 v2

> 목적: 모든 블로그 글이 같은 사람이 쓴 것처럼 일관된 톤·형태를 갖추게 한다.
> 적용 범위: `blog_generator.py`가 생성하는 모든 본문. 발행 전 자동 검토 대상.

---

## 1. 글자 크기 (네이버 스마트에디터 기준)

| 요소 | 크기 | 굵기 |
|------|------|------|
| 제목 | 에디터 기본값(자동, 약 28~32px) | 자동 |
| 소제목 (##) | 19px | 굵게 |
| 본문 | 15px (기본값 유지) | 보통 |
| 강조 문장 (시그니처·핵심 문장) | 15px | 굵게 |
| 표 안 텍스트 | 15px | 헤더 행만 굵게 |

- 소제목과 본문은 반드시 크기 차이를 둬서 위계를 눈으로 구분되게 한다.
- 본문 안에서 크기를 임의로 키우거나 줄이지 않는다 (강조는 크기가 아니라 굵기로).

## 2. 문장 부호

| 상황 | 규칙 |
|------|------|
| 문장 종결 | 마침표(.) 필수. 느낌표(!) 금지 |
| 물음표 | 진짜 질문일 때만 (①-C 반전 질문형, ⑨ 낮은 문턱형 등). 수사적 남발 금지 |
| 말줄임(…) | 문단당 최대 1회. 여운형 마무리에만 |
| 줄표(—) | 속마음 대독·상황 전환에 사용 가능 (예: "이 검색, 보통 병원 다녀온 날 밤에 하십니다 —") |
| 쉼표 | 한 문장에 3개 이상 금지 — 넘으면 문장을 둘로 쪼갠다 |
| 따옴표 | 인용·직접화법에만 사용 ("13년 부었는데..."). 강조 목적의 남발 금지 |
| 이모지·특수기호(★☆✓ 등) | 본문 금지. 표 안 상태 표시(✅ 등)는 예외적으로 허용 |

## 3. 문단 간격

- 한 문단 = 2~4문장. 그 이상 길어지면 문단을 나눈다.
- 문단과 문단 사이 반드시 빈 줄 1개 (Enter 2번 = 빈 줄 1개 삽입 효과).
- 소제목 바로 다음 문단은 빈 줄 없이 붙여 쓴다 (소제목이 곧 그 문단의 표지이므로).
- 표·이미지 앞뒤에는 문단 구분을 명확히 하기 위해 반드시 빈 줄을 둔다.
- **화제가 전환되는 지점**(소제목 섹션이 끝나고 다음 섹션으로 넘어가기 직전, CTA 섹션 시작 직전)에는 구분선(마크다운 `---`)을 삽입해 큰 호흡 단위를 시각적으로 나눈다.
  - 단위는 "문단"이 아니라 "섹션/화제 블록"이다 — 개별 문단(2~4문장)마다 넣지 않는다. 매 문단마다 넣으면 모바일에서 오히려 산만해진다.
  - 글 1편(1,500~3,000자)당 구분선 3~5개가 적정. 소제목(##) 개수와 비슷한 빈도로 맞춘다.

## 4. 강조 표시 방법

- **굵게(bold)**만 사용한다. 밑줄·기울임·글자색 강조는 쓰지 않는다 (브랜드 톤 = 절제된 전문가).
- 굵게 처리 대상 (우선순위 순):
  1. 소제목(##) 전체
  2. 시그니처 문장(⑦) — 한 글에 등장하면 반드시 굵게
  3. 핵심 숫자 1~2개 (전체 숫자를 다 굵게 하지 않는다 — 정말 중요한 것만)
  4. 정직함(⑤)·확신의 절제(⑩) 문장 중 한 문장 (독자가 스크롤만 해도 읽히도록)
- 한 문단에 굵게 표시는 최대 1곳. 남발하면 강조가 무의미해진다.

## 5. 문체 (어투)

- 문장 종결: **"-습니다/-니다" 통일**. "-해요"체·반말·명령형("~하세요!") 금지.
- 주어는 대부분 생략. "저는"은 시그니처(⑦) 문장이나 1인칭 고백(⑧)에서만 명시적으로 사용.
- 독자 지칭: "여러분" 남발 금지 — 대신 상황으로 지칭 ("이 경우엔", "그렇다면").
- 결론 먼저, 근거는 그다음 (두괄식). 문단 순서를 "결론 → 이유 → 예외"로 고정.
- 한 문장 길이: 평균 25~40자. 60자 넘는 문장은 쉼표 지점에서 둘로 쪼갠다.
- 능동태 우선. "~됩니다/~되어집니다" 같은 이중 피동 금지.

## 6. 금지 표현 (PART 5 금지 목록과 연동)

- "무조건 / 반드시 / 최고의 / 유일한 / 꼭"
- "고객님의 소중한 보험", "저는 정직한 설계사입니다" 류 자기 주장형 문장
- "~하시면 후회합니다" 류 공포 마케팅
- 느낌표, 이모지
- 특정 보험사·상품명 비교 우위 서술

## 7. 표(테이블) 생성 가이드라인

표는 정보를 스캔하기 쉽게 만드는 도구다. 헤더 행이 본문 행과 구분되지 않으면 표의 목적이 사라진다 — 헤더 행은 반드시 **강조 또는 배경색 변경**으로 구분한다.

| 규칙 | 적용 |
|------|------|
| 헤더 행(첫 줄) 강조 | 마크다운 작성 시 반드시 `**굵게**`로 감싼다. 예: `\| **항목** \| **현재** \| **최적화 후** \|` |
| 헤더 행 배경색 | 딥 네이비(`#1A2F5E`) 배경 + 흰 텍스트, 또는 라이트 그레이(`#E8ECF0`) 배경 중 택1 |
| 본문 행 배경 | 줄무늬 없이 오프화이트(`#F7F8FA`) 단색 — 헤더만 튀게 유지 |
| 숫자 컬럼 정렬 | 우측 정렬 (`_context/design-style-guide.md` 레이아웃 원칙과 동일) |
| 열 개수 | 3열 고정 권장 (발행 자동화가 3열 기준으로 셀을 채움) |
| Before/After 표 | 왼쪽 열 = 레드톤 문구, 오른쪽 열 = 그린·오렌지톤 문구로 대비 |

- 자동 발행(`naver_blog_poster.py`)은 헤더 행에 자동으로 **굵게** 서식을 적용한다.
- 배경색은 네이버 에디터의 표 서식 도구에서 발행 후 수동으로 지정한다 (자동화 미지원 — 굵게만으로도 구분 요건은 충족된다).

## 8. 이미지 생성 가이드라인 (v2 — 따뜻함·신뢰감 중심)

> 기존 기준(다크 네이비 + 비비드 오렌지의 차갑고 강한 대비)은 인스타 카드뉴스 전용으로 유지한다. **블로그 이미지는 이 기준을 따로 적용**한다. 블로그 독자는 이미 불안한 상태로 검색해 들어오므로, 이미지 톤 자체가 "차분하게 설명해주는 신뢰가는 선배"의 인상을 줘야 한다.

### 톤 & 색감

| 요소 | 기존(카드뉴스용) | 블로그용 (신규) |
|------|-----------------|-----------------|
| 배경 | 다크 네이비 `#0D1B2A` | 웜 아이보리 `#F7F1E8` 또는 채도·명도를 높인 소프트 네이비 `#2C4270` |
| 포인트 컬러 | 비비드 오렌지 `#E07C3A` | 톤다운 앰버 `#D98E4F` |
| 분위기 | 강한 대비, 각진 카드 | 부드러운 그림자, 둥근 모서리, 여백 넉넉 |
| 조명(photo 스타일) | 명시 없음 | 따뜻한 자연광/은은한 실내조명(골든아워 톤) — 차갑고 클리니컬한 블루톤 지양 |

### 스타일별 지침

- **infographic**: 웜톤 배경 + 둥근 카드/아이콘. 숫자는 여전히 크게 강조하되 색상은 톤다운 앰버 사용. 각지고 차가운 대비 대신 부드러운 그림자로 위계를 만든다.
- **photo**: 따뜻한 나무 책상, 커피잔, 창가 자연광, 손으로 서류를 짚는 장면 등 "믿을 수 있는 사람과 마주 앉은 느낌". 얼굴 노출 금지 원칙은 그대로 유지(뒷모습·손·사물 중심).
- 공통 금지: 차가운 형광 조명, 삭막한 사무실 느낌, 스톡사진 특유의 인위적 미소.

### 사이즈 (기존 대비 절반)

| 이미지 종류 | 기존 | 변경 |
|------------|------|------|
| 대표 이미지 | 1200 × 630px | **600 × 315px** |
| 본문 인포그래픽 (표시 폭 기준) | 최대 800px | **최대 400px** |

- nanobanana(Gemini 이미지 생성 모델)는 절대 픽셀 크기가 아닌 `aspect_ratio`만 지정 가능하다. 대표 이미지는 `aspect_ratio: "16:9"`, 본문 인포그래픽은 `aspect_ratio: "4:3"` 또는 `"3:2"`로 생성한다.
- 생성 후 네이버 에디터에 삽입할 때 이미지 크기 조절 핸들로 위 표시 폭(대표 600px / 본문 400px) 기준까지 축소한다.
- 이미지가 작아진 만큼 본문 텍스트가 상대적으로 더 부각된다 — 이미지는 보조 자료, 텍스트가 메인이라는 원칙에 부합한다.

## 9. 신선도 신호 표기 (AI 검색 노출 보강)

`blog-daily-automation-strategy.md` 4.1의 신선도 신호를 정확히 어떻게 쓰는지 정한다.

| 요소 | 규칙 |
|------|------|
| 위치 | 본문 최하단, CTA 문단(PART 2-A) 바로 위. 별도 문단으로 분리 |
| 문구 | "이 글은 YYYY.MM.DD 기준으로 정리했습니다." 형식 고정 (날짜는 발행일) |
| 글자 크기·굵기 | 15px, 보통(굵게 아님) — 본문과 동일 취급, 강조 대상 아님 |
| 구분선 | 바로 위에 `---` 삽입해 CTA 섹션과 시각적으로 분리 (3장 화제 전환 규칙과 동일) |

이 한 줄은 독자를 위한 장식이 아니라 검색·AI 시스템에 주는 신선도 신호다 — 그래서 본문 어투(두괄식·굵게 강조)와 의도적으로 다르게, 눈에 띄지 않는 사무적인 톤으로 고정한다.
