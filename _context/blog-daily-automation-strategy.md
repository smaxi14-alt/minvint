# 증권 진단소 네이버 블로그 — 1일 1글 완전자동화 6개월 전략서

> 이 문서는 `_context/` 운영 헌장의 하위 문서로, 이후 모든 블로그 자동화 코드
> (`blog_generator.py`, `blog_tracker.py`, `naver_blog_poster.py`, `scheduler.py`)의
> 기준이 된다. 매일 오전 11시, 사람 개입 없이 1건이 발행되는 것을 전제로 설계했다.

## 0. 대전제 재확인

블로그를 키우는 게 목표가 아니라 **니즈 있는 낯선 사람이 검색으로 들어와 카톡 채널로 넘어가는 통로**를 만드는 게 목표다. 이웃·방문자 수는 측정하지 않는다. 신청 1건이 방문 1,000명보다 크다.

원래 계획은 "주 2글 × 12주 = 24글"이었다. 이번 요청으로 **1일 1글 × 182일**로 확장한다. 이 전환이 만드는 새로운 위험은 두 가지다.

1. **소재 고갈·중복**: 24개면 손으로도 중복을 피하지만, 182개는 시스템 없이는 반드시 겹친다.
2. **품질 저하**: 사람이 매일 리뷰하지 않으므로, 브랜드 규칙 위반이 그대로 발행될 수 있다.

이 문서의 3~4장은 (1)을, 7장은 (2)를 해결하기 위한 장치다.

## 1. 키워드 뱅크와 조합 규모

확보된 키워드 뱅크는 3개 tier로 구성되며, 조합 방식은 아래와 같다.

| Tier | 구성 | 조합 계산 | 총 조합 수 |
|------|------|-----------|-----------|
| A. 지역 (1순위, 전환 최강) | locations(27) × topics(10) × actions(8) | 27×10×8 | **2,160개** |
| B. 불안·후회 (2순위) | situations(22) × angles(8) | 22×8 | **176개** |
| C. 트리거 이벤트 (3순위) | events(18) × angles(6) | 18×6 | **108개** |
| **합계** | | | **2,444개** |

182일 대비 2,444개는 **13.4배** 여유가 있다. 다만 tier별 여유율은 균일하지 않다.

| Tier | 182일 배분 목표 | 조합/배분 배율 | 비고 |
|------|-----------------|---------------|------|
| A | 약 109일 (60%) | 2,160 / 109 ≈ **19.8배** | 여유 충분, 지역×토픽 재조합만으로도 6개월 이상 지속 가능 |
| B | 약 51일 (28%) | 176 / 51 ≈ **3.5배** | tier 중 가장 타이트함 — 소진 감시 필요 |
| C | 약 22일 (12%) | 108 / 22 ≈ **4.9배** | 여유 있으나 A만큼은 아님 |

**결론**: 182일 무중복은 산술적으로 보장된다. 단 B(불안·후회) tier는 여유율이 3.5배로 가장 낮으므로, 6개월을 넘겨 연장 운영할 경우 B는 가장 먼저 "situation + 연령대(40대/50대) 세분화" 같은 신규 차원을 추가해 조합을 늘려야 한다.

절대 사용하지 않는 패턴(`banned_keyword_patterns`)은 생성 전 필터가 아니라 **7장의 발행 전 QC**에서 정규식으로 최종 차단한다(생성 단계에서 걸러도 프롬프트 변형으로 재등장할 수 있기 때문).

## 2. 6개월(182일) 로드맵

12주 계획을 4개 Phase, 182일로 확장한다. Phase 경계는 "무엇을 검증했는가"를 기준으로 나눴다.

| Phase | 기간 | 일수 | 목적 | 지역(A) | 불안(B) | 트리거(C) |
|-------|------|------|------|---------|---------|-----------|
| **1. 기반구축** | Day 1~14 (2주) | 14일 | 프로필·신뢰자산 확립, 지역 키워드 초기 노출 | 10일 (71%) | 3일 (21%) | 1일 (7%) |
| **2. 미끼글 집중** | Day 15~70 (8주) | 56일 | 지역+불안 키워드 대량 노출, 검색 인덱싱 구간 | 40일 (71%) | 14일 (25%) | 2일 (4%) |
| **3. 트리거+사례 확장** | Day 71~126 (8주) | 56일 | 생애 이벤트·실사례로 전환율 높은 글 비중 확대 | 32일 (57%) | 14일 (25%) | 10일 (18%) |
| **4. 반복·보강·재활용** | Day 127~182 (8주) | 56일 | 네이버 통계로 실제 걸린 키워드 확인 후 보강, 불안 tier 비중 재상향 | 27일 (48%) | 20일 (36%) | 9일 (16%) |
| **합계** | 182일 | 182일 | | **109일 (60%)** | **51일 (28%)** | **22일 (12%)** |

### Phase별 상세

- **Phase 1**: 원문의 "1~2주 프로필 정비+신뢰 자산 글" 취지. 첫 3~4일은 "시작한 이유", "진단서란 무엇인가" 같은 신뢰 자산형 글을 지역 키워드(예: 전주 완산구+실손보험+점검)와 결합. 인덱싱 전 구간이므로 전환보다 **자산 축적**이 목표.
- **Phase 2**: 원문의 "3~6주 미끼 글 집중"을 8주로 확장. 지역×토픽×액션 조합을 최대 밀도로 소진, 매주 지역 4~5편+불안 1~2편 유지. Day 70에 네이버 검색 통계 1차 점검.
- **Phase 3**: 원문의 "7~10주 트리거+진단 사례" 구간. 트리거(암 진단, 사망보장 공백 등)는 전환 강도가 가장 높지만 검색량이 낮으므로, 지역 키워드로 쌓은 검색 신뢰 위에 얹는다. "증권 진단 실사례" 비중이 이 구간에서 최고치.
- **Phase 4**: 원문의 "11~12주 보강·전환율 점검"을 6주로 확장. Day 70·126 통계로 반응 좋았던 조합에 **다른 후킹 유형·다른 사례**로 재접근(캐니벌라이제이션 방지는 3장). B tier를 36%까지 올리는 이유는 원문에서 B를 "니즈가 가장 명확한 tier"로 규정했고, 데이터가 쌓인 시점에 전환율 최적화가 합리적이기 때문.

### 기본 요일 로테이션 (Phase 내 기본값)

| 요일 | 기본 tier | 비고 |
|------|-----------|------|
| 월·화·목·금 | A (지역) | 주 4회 |
| 수·토 | B (불안) | 주 2회 |
| 일 | C (트리거) | 주 1회 |

이 로테이션대로면 주당 A4:B2:C1 = 57:29:14 비율이 나온다. Phase별 목표 비율(표 상단)과 다를 경우, 스케줄러가 해당 Phase의 목표치에 맞춰 특정 요일의 tier를 주 단위로 오버라이드한다(예: Phase 1에서는 수요일도 A로 덮어써 71%까지 끌어올림). 요일 로테이션은 "기본값"이고 Phase 비율표가 "우선순위"다.

## 3. 중복 방지 시스템

### 3.1 현재 상태의 공백

`blog_tracker.py`는 현재 `series`·`hook_type`·`metaphor_domain`·`signature` 단위 로테이션만 관리한다. **키워드 조합 단위 dedup이 없다.** "전주 완산구+실손보험+점검" 조합을 이미 썼는지는 지금 추적되지 않는다 — 방치하면 182일 안에 반드시 재등장한다.

### 3.2 추가할 필드: `keyword_hash`

`blog_tracker.py`의 `log_post()`에 신규 파라미터를 추가한다.

```python
def log_post(
    series: str,
    tier: str,              # "A" | "B" | "C"
    keyword_hash: str,      # 정규화된 조합 문자열 (아래 규칙)
    hook_type: str = "",
    metaphor_domain: str = "",
    signature: str = "",
    elements_used: list[str] | None = None,
):
    ...
```

정규화 규칙:

| Tier | 해시 원본 | 예시 |
|------|-----------|------|
| A | `location\|topic\|action` | `전주 완산구\|실손보험\|점검` |
| B | `situation\|angle` | `실손보험 중복가입\|확인법` |
| C | `event\|angle` | `암 진단 후 청구\|청구 노하우` |

2,444개는 해시가 필요할 만큼 큰 규모는 아니지만, 파일 용량과 diff 가독성을 위해 `hashlib.sha1(...).hexdigest()[:12]`로 축약 저장을 권장한다.

### 3.3 셔플-소진 방식 (랜덤 재시도보다 우선 권장)

랜덤 추첨 후 "이미 썼으면 재추첨" 방식은 조합이 소진될수록 재시도가 급증한다(B tier는 51/176=29% 시점부터 잦아짐). 대신:

1. 운영 시작 시점(Day 1)에 각 tier의 전체 조합을 생성하고, **고정 시드로 1회 셔플**해 순서를 확정한다.
2. 매일 스케줄러가 오늘의 tier(2장 로테이션표 기준)를 정하면, 해당 tier의 셔플된 리스트에서 **아직 소비되지 않은 첫 항목**을 순차로 꺼낸다.
3. 소비된 조합은 `used_keyword_combos.json`에 tier별 리스트로 append한다(사용일자 포함).
4. 이 방식은 "재시도"가 원천적으로 필요 없고, 182일 종료 시점까지 무중복이 수학적으로 보장된다(A는 109/2,160, B는 51/176, C는 22/108만 소비하므로 어떤 셔플이든 전량 미소진).

### 3.4 시리즈 배정 (기존 5개 시리즈로 라벨링)

키워드 조합이 정해지면 아래 규칙으로 5개 기존 시리즈 중 하나에 자동 배정한다(액션/상황/이벤트 기준 분기).

| Tier | 분기 기준 | 배정 시리즈 |
|------|-----------|-------------|
| A | action = 진단/무료진단/증권분석 | 증권 진단 실사례 |
| A | action = 점검/상담/비교/재설계 | GA 설계사의 솔직한 말 |
| A | action = 리모델링 + topic이 김부장 핵심 관심사(실손/암/종신) | 보험료 다이어트 |
| A | topic = 자동차/화재/사업자/치아/운전자보험 (topic·action 무관 우선 재배정) | 40대 보험 공백 시리즈 |
| B | situation = 보험료 과다/줄이는법 계열 | 보험료 다이어트 |
| B | situation = 해지 손해/중복 특약/방치 계열 | 증권 진단 실사례 |
| B | situation = 노후 실손 전환/은퇴 후 부담 계열 | 은퇴 현금흐름 |
| B | situation = 맞벌이 부부 중복 | 은퇴 현금흐름 또는 최근 미사용 시리즈 |
| C | event = 질병·사고(암/뇌혈관/심장/수술) | 증권 진단 실사례 |
| C | event = 생애주기 공백(사망보장/출산/독립/결혼/내집마련) | 40대 보험 공백 시리즈 |
| C | event = 은퇴·퇴직·사업자 전환 | 은퇴 현금흐름 |
| C | event = 부모님 치매·간병 | 40대 보험 공백 시리즈 (또는 실제 청구 사례 有 시 증권 진단 실사례 우선) |

이 배정은 `blog_tracker.py`의 기존 `series` dedup(최근 N일 회피)과 맞물린다 — **키워드 dedup(3.3) + 시리즈 dedup + 후킹유형/비유분야 dedup**, 3중 로테이션이 겹치면 같은 글이 두 번 나올 확률은 0에 가깝다.

### 3.5 소재 반복 감지 (보조 장치)

키워드 조합이 달라도 문장 표현이 비슷해질 수 있다. 발행 전 QC(7장)에서 **최근 14일 제목·첫 문장의 문자열 유사도**를 계산해 임계치(예: 0.6) 이상이면 1회 재생성을 트리거한다. 완전한 방지책이 아니라 "명백한 재탕"만 걸러내는 최소 방어선이다.

## 4. 검색 노출 극대화 — 키워드 배치 원칙

다양한 키워드를 "장악"한다는 것은 소재를 다양화하는 것과, 그 소재를 네이버가 정확히 인덱싱하도록 배치하는 것 두 가지다.

| 배치 위치 | 원칙 |
|-----------|------|
| 제목 | `[지역/상황] + [토픽] + [액션]` 3요소를 자연어 문장으로 결합. "전주 완산구 실손보험 점검, 이렇게 확인하세요" 형태. 시리즈명은 제목에 넣지 않는다(검색자는 시리즈를 모른다). |
| 본문 첫 200자 | 핵심 키워드 1~2회 자연 반복(과도한 반복은 스팸 판정 리스크). 블록1 후킹 문장 안에 자연스럽게 포함. |
| 소제목(H3) | 제목과 동일 키워드 반복 대신 **동의어 로테이션**(점검/진단/리모델링/비교를 상황에 맞게 교차 사용) — 캐니벌라이제이션(같은 조합 반복 사용 시 검색엔진이 두 글을 중복 문서로 인식) 방지. |
| 이미지 alt 텍스트 | `지역 + 토픽 + 시리즈명` 조합(예: "전주 실손보험 점검 증권 진단 실사례"). |
| 해시태그 | 지역 1~2개 + 토픽 1개 + 시리즈명 1개 + 액션 1개, 총 4~5개로 제한(과다 태그는 오히려 신호 희석). |

Phase 4에서는 네이버 통계로 확인된 **실제 유입 키워드**를 우선순위 상단에 반영해, 위 5개 위치의 동의어 로테이션 풀을 재조정한다.

## 5. Phase별 글쓰기 전략

`_context/blog-writing-program.md`의 STEP1(글 유형 판정)과 5블록 조립을 Phase 목적에 맞게 가중한다.

| Phase | 우선 글 유형 | 필수 요소 | 선택 요소 | 시리즈 가중 |
|-------|-------------|-----------|-----------|-------------|
| 1. 기반구축 | 지역·신뢰형 | ④친절함 ⑦소신·기준 ⑨낮은문턱 | ⑥실전서사 ⑧인간적틈 | GA 설계사의 솔직한 말 (신뢰 자산형) |
| 2. 미끼글 집중 | 정보·해설형 + 지역·신뢰형 | ①공감 ②전문성 ③쉬운설명 | ④친절함 ⑤정직함 ⑩확신의절제 | 보험료 다이어트, 증권 진단 실사례 |
| 3. 트리거+사례 확장 | 사례·서사형 | ①공감 ⑥실전서사 | ⑤정직함 ⑦소신 ⑧인간적틈 | 증권 진단 실사례, 40대 보험 공백 시리즈 |
| 4. 반복·보강·재활용 | 전 유형 순환 + 셀프체크·도구형 | ③쉬운설명 ⑤정직함 | ②전문성 ⑨낮은문턱 ⑩확신의절제 | 반응 좋은 시리즈 상향 배분(데이터 기반) |

5블록 조립·로테이션 규칙(후킹 유형 2회 연속 금지, 비유 분야 3회 연속 금지)은 Phase와 무관하게 항상 적용된다 — 이 규칙 자체가 `blog_tracker.py`의 기존 dedup 로직이다.

## 6. 완전 자동화 아키텍처 (매일 11:00 KST, 무인)

```
[10:00] 오늘의 조합 결정 — Phase/요일 로테이션(2장) → 셔플-소진 리스트(3.3)에서 미소비 조합 추출 → 시리즈 자동 배정(3.4)
        ↓
[10:05] 텍스트 생성 — blog_generator.py(Claude API). keyword_spec 전달 → 제목·본문·image_specs(≥5) 생성.
        실패 시 1회 재시도, 재실패 시 STATUS=GEN_FAILED 로그 후 당일 스킵
        ↓
[10:15] 발행 전 QC 게이트(7장) — 금지표현/얼굴노출/광고심의 정규식 스캔 + 최근 14일 유사도 검사(3.5).
        FAIL 시 즉시 중단 → 예비 evergreen 글로 대체 또는 당일 스킵 + 알림 로그
        ↓
[10:25] 이미지 생성 — mcp__nanobanana__generate_image(model:"pro" 고정), image_specs 각 항목 순차 호출.
        다른 이미지 API 폴백 절대 금지(과거 imagen-4.0-generate-001 직접 호출 시 한글 텍스트 깨짐 전례).
        프롬프트에 "지정된 문구 외 텍스트/로고/워터마크 추가 금지" 명시. 실패 시 동일 프롬프트로 최대 2회 재시도.
        5개 미만 생성 시 STATUS=IMAGE_INCOMPLETE 로그, 3개 이상이면 그대로 진행, 미만이면 발행 중단
        ↓
[10:45] 인프라 프리플라이트(8장) — 화면 잠금 감지(잠겨 있으면 즉시 중단, 재시도 없음) + 네이버 세션 유효성 확인.
        실패 시 STATUS=SESSION_EXPIRED 로그, 발행 보류
        ↓
[11:00] 발행 — naver_blog_poster.py(Selenium+pyautogui, 로컬 PC 전용). 제목·본문·이미지 순차 업로드.
        실패 시 재시도 정책(8장 표) 적용, 성공 시 발행 URL 확보
        ↓
[11:10] 로그 기록 — blog_tracker.py에 series/tier/keyword_hash/hook_type/metaphor_domain/signature/
        elements_used/이미지 개수/발행 URL/STATUS 저장, used_keyword_combos.json에 소비 조합 append
```

이미지 무인화의 핵심은 **"대체 이미지 API로 폴백하지 않는다"**는 원칙이다. 실패 시 재시도만 하고, 그래도 실패하면 이미지 개수가 줄어든 채로 발행하거나 발행 자체를 보류한다 — 절대로 Imagen 계열이나 다른 생성기로 전환하지 않는다.

## 7. 품질 안전장치 (사람 없는 QC 게이트)

### 7.1 자동 스캔 규칙

| 검사 항목 | 방법 | 예시 정규식/규칙 |
|-----------|------|------------------|
| 금지 표현 | `banned_keyword_patterns` 정규식화 | `(최고|1위|완벽|무조건|필수|꼭\s*(가입|드셔야)|보험\s*추천|좋은\s*보험|보험\s*순위|인기\s*보험)` |
| 과장 광고 | brand-guidelines 금지어 | `(최고|완벽한|꼭\s*가입)` |
| 얼굴노출 | 본문 및 image_specs 텍스트 스캔 | `(얼굴|셀카|인물\s*사진|프로필\s*사진|face|selfie|portrait of a person)` 매칭 시 이미지 프롬프트 재작성 강제 |
| 광고심의 리스크 | 특정 보험사명 리스트 매칭 | 주요 손보·생보사명 리스트에서 2개 이상 동시 등장 시 차단(상품 비교 프레임 위반) |
| CTA 단일성 | 외부 링크 검사 | 카톡 채널 링크 외 `https?://` 패턴이 본문에 있으면 차단(브랜드 규칙: 외부 링크는 프로필 경유만) |
| 두괄식 최소 검증 | 첫 300자 내 숫자 존재 여부 | `\d` 매칭 0회면 경고(차단은 아님, 로그만) |

### 7.2 솔직한 리스크 인정 — 이미지 텍스트는 완전히 못 잡는다

과거 카드뉴스 파이프라인에서 nanobanana가 지정하지 않은 임의의 태그라인을 이미지에 삽입한 사례가 있었다. **텍스트 정규식으로는 절대 잡을 수 없는 리스크**다 — 이미지 내부에 렌더링된 문구이기 때문이다. 사람이 매일 리뷰하지 않는 이상 완전히 제거되지 않는다.

완화책: ① **프롬프트 강제 조항** — 모든 image_spec 끝에 "지정된 텍스트 외 문구·로고·워터마크 추가 금지" 고정 삽입. ② **주간 배치 감사** — 완전 무인이되 주 1회(예: 일요일 저녁) 그 주 발행 7건의 이미지만 사람이 훑어보는 경량 체크포인트 유지, 문제 발견 시 이미지만 교체(본문 삭제 불필요). ③ **로컬 원본 보관** — 발행 이미지를 `automation/data/blog_images/`에 유지해 사후 교체를 즉시 가능하게 함.

이건 "무인 자동화가 얻는 것(시간)"과 "잃는 것(즉각적 인간 검수)"의 트레이드오프다. 완전 제거가 아니라 **주간 단위로 손실을 제한**하는 것이 현실적 목표다.

## 8. 운영 리스크 — 인프라

로컬 PC 기반 Selenium/pyautogui 자동화이므로, 클라우드 스케줄러에는 없는 리스크가 발생한다.

| 리스크 | 발생 조건 | 완화책 |
|--------|-----------|--------|
| 네이버 로그인 세션 만료 | 쿠키 유효기간 초과, 보안 정책 강제 로그아웃 | 발행 전 마이페이지 접속으로 세션 프리체크. 실패 시 발행 보류+로그, 주 1회 수동 재로그인 |
| 화면 잠금 상태에서 pyautogui 실패 | 잠금화면 위 클릭·키입력 무의미 | `ctypes`로 전경 윈도우가 `LockApp`인지 감지, 잠겨 있으면 즉시 중단(재시도 없음). 화면 자동 잠금·화면보호기 비활성화 고정 |
| PC 절전·꺼짐 | 절전 진입, 정전, 예기치 않은 재부팅 | 전원 옵션 "절전 안 함"+"AC 연결 시" 고정. Task Scheduler "전원 켜져 있을 때만 시작", "누락 시 즉시 실행" 적용 |
| pyautogui 좌표 깨짐 | 해상도·DPI 배율 변경, 창 크기 변경 | 고정 해상도 유지, 좌표 클릭보다 Selenium 셀렉터 우선, pyautogui는 OS 네이티브 대화상자(파일 업로드)에만 한정 |
| 발행 중 예외(요소 못 찾음 등) | 네이버 에디터 UI 변경, 네트워크 지연 | 재시도 정책(아래) 적용, 최종 실패 시 캐치업 없이 STATUS=FAILED 기록 후 스킵(중복 발행 방지 우선) |

## 9. 측정 — 3개 지표와 6개월 마일스톤

측정 지표는 3개만 본다: **검색 유입 키워드 수(네이버 통계) / 채널 클릭 수 / 진단 신청 수**. 아래 수치는 가설적 목표치이며, Phase 2 종료 시점부터 실측 데이터로 매월 보정한다.

| 시점 | 검색 유입 키워드 | 채널 클릭 | 진단 신청(누적) |
|------|-----------------|-----------|-----------------|
| Day 14 (Phase 1 종료) | 0~소수 (인덱싱 지연 구간) | 소수 | 0~1건 |
| Day 70 (Phase 2 종료) | 10개 이상 | 주 5회 이상 | 3~5건 |

신청 1건이 방문 1,000명보다 크다는 원칙은 6개월 내내 유지한다 — 방문자 수·이웃 수는 이 문서의 어떤 마일스톤에도 포함하지 않는다.

## 10. 채널 생태계 역할 분담 (6개월 타임라인 반영)

역할 구조는 **쓰레드(후크·가설 검증) → 블로그(깊이·신뢰·SEO 자산, 시너지 1위) → 인스타그램 → 유튜브 → 카톡(전환 종착)** 순으로 고정한다.

- **Phase 1~2**: 쓰레드에서 매일 올라오는 후크 중 댓글 반응이 폭발한 주제만 블로그 소재 후보로 승격한다(검증 안 된 주제에 시간 투자 금지 원칙 유지). 이 구간에서는 키워드 뱅크 기반 자동 소재가 메인이고, 쓰레드발 소재는 보조.
- **Phase 3**: 블로그에 쌓인 "증권 진단 실사례" 글이 늘어나면서, 인스타 카드뉴스가 이 사례들을 압축 재가공하는 소재원이 된다.
- **Phase 4**: 블로그 자산(182일 중 126일 치)이 유튜브 스크립트의 근거 자료로 재활용되기 시작한다 — 블로그가 "권위·깊이 증명"의 원본 소스 역할을 하는 구간.
- **상시**: 블로그 본문에는 외부 링크를 직접 넣지 않는다. 모든 채널 이동은 프로필 경유로 고정한다.
